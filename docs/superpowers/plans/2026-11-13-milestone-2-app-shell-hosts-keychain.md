# Milestone 2: App Shell, Hosts and Keychain (local only) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A runnable macOS app with the Termius-style window, sidebar, Hosts screen (groups, tags, search, cards, Host Details panel with autosave) and Keychain screen (identities, key generation and import), storing everything locally and encrypted.

**Architecture:** All logic lives in a new `AppCore` library in `Packages/CoreSSH` (Linux-testable: the local vault, encrypted vault file, `@Observable` view models, quick-connect parsing, SSH key generation and import). The macOS app in `App/` is a thin SwiftUI layer generated by XcodeGen, plus one Mac-only piece: the Keychain item that holds the local vault key.

**Tech Stack:** Swift 6, SwiftUI (macOS 14+), Observation, swift-crypto (`Crypto`, `_CryptoExtras`), XcodeGen, Xcode 27.

**Spec:** `docs/superpowers/specs/2026-11-13-termius-reimagined-design.md` (§5, §6, §8, §11 milestone 2) and Cory's Termius screenshots (described under Visual Reference below).

## Design change in this plan (for Cory's approval)

The design said local storage uses **SwiftData**. This plan replaces it with **one encrypted vault file**: every record (including passwords and keys) lives in `~/Library/Application Support/TermiusReimagined/vault.bin`, sealed with AES-256-GCM. Its key is the single item in the macOS Keychain, as already decided. Why:
- Everything is encrypted on disk, not just secrets.
- The file holds exactly the records the sync engine already uses (`PlainRecord` + dirty flags + `SyncState`), so plugging in sync in milestone 4 is direct.
- It can be tested here on Linux; SwiftData can't, which would mean many more test round-trips through your Mac.
- The data is small (hundreds of records), so loading it all into memory is fine.

## Global Constraints

- `AppCore` must not import SwiftUI, AppKit, SwiftData, Security or LocalAuthentication; it builds and tests on Linux (`source /usr/local/bin/swiftenv; cd Packages/CoreSSH && swift test`).
- View models are `@MainActor @Observable final class`; tests use `@MainActor` XCTest methods.
- Every saved edit goes through `LocalVault.save`, which sets `updatedAt = Timestamps.nextUpdate(previous: old.updatedAt)` and marks the record dirty. Deletes are tombstones (`deleted = true`), hidden from every list.
- Vault file format: `CoreJSON`-encoded `VaultFileContents` sealed with AES-256-GCM (`combined`), AAD = UTF-8 `"termius-reimagined-vault-v1"`. Writes are atomic (write temp file, then replace).
- Never delete or overwrite a vault file that fails to decrypt or decode: rename it to `vault.bin.unreadable-<timestamp>` and surface `VaultLoadError` to the UI.
- Mac app: bundle id `com.cwland.TermiusReimagined`, deployment target macOS 14.0, ad-hoc signed (`CODE_SIGN_IDENTITY: "-"`), App Sandbox off. Keychain item: generic password, service `com.cwland.TermiusReimagined`, account `local-vault-key`, not synchronizable.
- OS badges use generic SF Symbols in colored rounded squares — never trademarked distro or Apple logos.
- Only SSH (no telnet/serial). Connect buttons exist but are disabled with tooltip "SSH sessions arrive in milestone 3".

## Review Focus

1. **Unreadable vault file or missing/denied Keychain key** (new Mac, corrupted file, wrong key): never wipe data; the file is moved aside and the UI shows a clear error. → tests in Task 2.
2. **Odd quick-connect input:** `ssh root@10.0.0.5 -p 2222`, `[fe80::1]:22`, `user@host:2222`, bare `host`, surrounding spaces, empty string. → tests in Task 3.
3. **Deleting a group that has hosts and subgroups:** hosts and subgroups move to the deleted group's parent; nothing else disappears. → test in Task 3.
4. **Deleting an identity or key that hosts use:** the hosts keep working records with the reference cleared, and the UI can show how many hosts are affected before deleting. → tests in Task 3 and Task 8.
5. **Rapid autosave edits:** every keystroke-level save produces a strictly increasing `updatedAt`, the last value wins, and nothing is lost when switching hosts mid-edit. → tests in Task 5.

### Task 6: SSH key generation

**Files:** Create `SSHKeys/OpenSSHFormat.swift`, `SSHKeys/SSHKeyGenerator.swift`; Test `SSHKeyGeneratorTests.swift`

**Interfaces:**
- Produces:
  - `struct GeneratedKey: Equatable { var keyType: SSHKey.KeyType; var publicKey: String /* "ssh-ed25519 AAAA… comment" */; var privateKey: String /* PEM text */ }`
  - `enum SSHKeyGenerator { static func ed25519(comment: String) -> GeneratedKey; static func rsa4096(comment: String) throws -> GeneratedKey }`
  - Ed25519 private key is an unencrypted **OpenSSH** private key (`-----BEGIN OPENSSH PRIVATE KEY-----`, `openssh-key-v1` structure, cipher/kdf "none", 64-byte private = seed‖public, random check ints, padding 1,2,3…, base64 wrapped at 70 chars). RSA private key is PKCS#1 PEM (`-----BEGIN RSA PRIVATE KEY-----`) from `_RSA.Signing.PrivateKey(keySize: .bits4096)`; its public key line is `ssh-rsa` with `string "ssh-rsa" ‖ mpint e ‖ mpint n` parsed from the DER public key.
  - `enum OpenSSHFormat` helpers: `string(_:)`, `mpint(_:)` (two's-complement, leading 0x00 when high bit set), `uint32(_:)`, and a minimal DER reader for `RSAPublicKey ::= SEQUENCE { n INTEGER, e INTEGER }`.

